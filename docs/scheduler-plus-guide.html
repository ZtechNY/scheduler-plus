Section 1

Overview & the schedule list

Scheduler+ is a card on your Home Assistant dashboard. Each row is a schedule — a named set of on/off rules for one or more devices (lights, switches, or a thermostat). This is the screen you'll come back to most.

Each row shows, left to right:

  • An on/off switch — enables or disables that whole schedule immediately, without opening it.
  • The name, followed by its device type, entity count, and rule count (e.g. "Switch · 1 entity · 1 rule").
  • A status line underneath, when relevant — Next: On Fri, 6:00 AM, an "Inactive until…" note, or a "Paused through…" note (more on these in later sections).
  • Row actions on the right: Edit, Duplicate, Pause/Resume, and Delete.

The four icons in the card's header are shortcuts, covered in their own sections below:

IconOpens
👤🕐My preferences — your own weekday/weekend/working-hours defaults (§8)
📅🕐Day view — a read-only report of what's scheduled on a day or week (§7)
📅➕Quick event — a fast one-off on/off for a single date (§6)
▦➕From template — start a new schedule from a saved template (§9)

To add a brand-new schedule, use the Add schedule button at the bottom of the card.

Section 2

Creating a schedule

A schedule ties one or more devices to one or more rules. Click Add schedule to open the editor.

  1. Name the schedule something a colleague would recognize at a glance — "Office lights", "Office AC", "Front Hallway Evening".
  2. Choose the Device type: Lights & Switches or Climate. This determines which entities you can pick and which action options appear later when you build a rule.
  3. Leave Enabled on (the default) unless you're building this ahead of time and don't want it to run yet.
  4. Leave Active period at "Always active" for a normal, year-round schedule. This field is for seasonal schedules — see §4.
  5. Use the Entities search box to find and check off the devices this schedule should control, then click Add selected. You can select several at once.
  6. Click Add rule to define when things turn on and off — see §3. A schedule with no rules does nothing.
  7. Click Save.
Section 3

Adding rules

A rule says: on these days (or dates), turn on at this time, turn off at that time, and do this action. A schedule can have several rules — for example, one for weekdays and a different one for weekends.

Name, enabled, and starting from a template

Give the rule a short name ("Weekday hours", "Weekend"). The Start from template button at the top lets you pre-fill everything below from a rule you've saved before — see §9.

Days

Tap individual day chips, or use a preset: Every day, Weekdays, Weekend, or After hours (fills in your own working-hours start/end from My Preferences, §8). "Weekdays" and "Weekend" use your own saved day split from My Preferences, not a fixed Mon–Fri assumption.

Date filter

By default a rule's Date filter is "Always" — it just follows the Days above, every week, forever. Changing it opens a panel with three more options:

  • Always — follows Days every week, no exceptions.
  • Only on these dates — the rule ignores Days entirely and fires only on the exact dates, date ranges, or special conditions you list. Good for one-off events or holiday hours.
  • Except these dates — the rule follows Days as normal, but skips any date you list. Good for "run every weekday, except during winter break."

Inside that panel you can add:

  • Specific dates — individual calendar days.
  • Date range — a start and end date, inclusive.
  • Special conditions (YidCal) — Shabbos, Yom Tov, Erev Shabbos, or Erev Yom Tov, driven by your YidCal calendar integration instead of fixed dates.
Good to know A YidCal condition can only be confirmed for today — so you won't see it listed under "Next event" on the card ahead of time, but the rule still fires correctly once that day actually arrives.

Time

Each rule has an On time and an Off time — you can turn either one off if you only want the rule to act on one side (see below). Each side's time can be:

  • Fixed time — a specific clock time, e.g. 6:00 AM.
  • Sunrise / Sunset — with an optional offset in minutes (e.g. "Sunset − 15").
  • A YidCal zman (הדלקות הנרות / מוצש״ק) — also with an optional offset, if your YidCal integration is set up.
On-only and off-only rules Turning off the On time or Off time switch makes the rule act on only that one side — useful for a rule that should just turn something off at a set time without ever turning it on (a curfew rule), or vice versa.

Action

What happens depends on the schedule's device type:

  • Switches — nothing to configure; the rule just turns the switch on and off.
  • Lights — turns on at whatever brightness the light was last set to, by default. Optional toggles let you pin a specific brightness or a gradual fade-in instead — most schedules don't need these.
  • Climate — choose the HVAC mode (Heat, Cool, etc.) and, optionally, a specific target temperature. There's also an Allow override toggle:
Allow override With Allow override on (the default), someone can walk up to the thermostat and change it, and it'll simply stay that way until the next scheduled event. Turn it off and the rule will keep enforcing its own setting for as long as it's active — if someone manually changes the thermostat, Scheduler+ waits a short grace period and then puts it back.
Section 4

Active period (seasonal scheduling)

This is a schedule-level setting (not per-rule) for schedules that should only run during part of the year — "Summer Hours" vs. "Regular Hours" sharing the same rooms.

  • Always active — the default; no seasonal restriction.
  • Only during these date ranges — the whole schedule is dormant except during the range(s) you add.
  • Except during these date ranges — the whole schedule runs as normal except during the range(s) you add.

A schedule that's currently outside its active period shows an "Inactive until …" note on the card instead of a "Next event" line, so it's obvious at a glance why it isn't doing anything right now.

Tip Pair two schedules on the same rooms — one set to "Only during" your summer range, one set to "Except during" that same range — instead of hand-editing one schedule's times twice a year.
Section 5

Editing, duplicating, pausing, deleting

Editing

Click the pencil icon on any schedule row to reopen the editor. All the same fields from §2–§4 apply.

Once a rule is saved, its row shows a compact summary (days and times) plus its own switch, so you can disable just that one rule without touching the rest of the schedule.

Duplicating

Click the duplicate icon to open a new schedule pre-filled with the same device type and rules as the one you clicked — handy for cloning a setup to another room. Nothing is saved until you edit the entities/name and click Save, so duplicating never affects the original.

Pausing

Sometimes you need to suppress a schedule temporarily — a snow day, a one-off closure — without touching its rules or remembering to turn it back on. Click the pause icon.

Pick the last date you want the schedule suppressed through, and click Pause. The schedule resumes automatically the following day — nothing to remember. While paused, the card shows a "Paused through …" note, and the pause icon becomes a Resume icon (▶) for a one-click early resume.

Enabling / disabling

The switch on the left of each row is the fastest way to turn a whole schedule off or on. Unlike Pause, this has no end date — it stays off until you flip it back.

Deleting

Click the trash icon and confirm. This is permanent — there's no undo.

Section 6

Quick events

For a one-off "just today" need — like keeping the gym lights on late for an event — Quick event skips the full Add schedule flow.

  1. Pick the entities.
  2. Optionally rename it (it defaults to "Event – [date]").
  3. Pick the date and the on/off times.
  4. Click Create.
Lights and switches only Quick event is scoped to lights and switches, with no brightness/fade options. For a one-off climate change, or anything recurring, use Add schedule instead.

Under the hood a Quick event is just a normal schedule with one rule for one date — it appears in the regular schedule list afterward, and you can edit or delete it like anything else. It doesn't clean itself up automatically once its date has passed, so it's worth deleting old ones occasionally.

Section 7

Day view & week view

A read-only report answering "what's actually going to happen, and when" — across every schedule, grouped by device type. Opened from the calendar-clock icon.

Day view

Each entry shows the on/off times, which schedule and rule produced it, the resulting action (e.g. "Cool · 69°"), and which entities are affected.

Week view

Click the Week toggle to switch views. Each column is one day; "Nothing scheduled" means exactly that for that day.

Section 8

My preferences

Your own weekday/weekend day split and working-hours start/end — used to power the Weekdays/Weekend/After hours quick-fill buttons when building a rule (§3). Opened from the person-clock icon.

This is personal, not shared Every signed-in user has their own copy of these settings. If a colleague's "Weekdays" preset fills in different days than yours, that's expected — it's each person's own saved preference, not one shared organization-wide default.
Section 9

Templates

Templates let you save a rule — or a whole schedule's worth of rules — and reuse it later without rebuilding it from scratch.

Saving a template

Both the rule editor and the schedule editor have a Save as template button at the bottom. Saving from the rule editor stores just that one rule, reusable later via Start from template inside any other rule of the same device type. Saving from the schedule editor stores the whole rule set, reusable via From template on the card header when starting a new schedule.

Using a template

From template (card header) shows your saved schedule templates with a Use button — picking one opens the normal Add schedule dialog pre-filled with that template's rules, so you still add the entities and review everything before saving. Start from template (inside the rule editor) works the same way for a single rule.

Section 10

Overlap warnings

When you save a schedule, Scheduler+ checks whether any of its rules would overlap with a different schedule on a shared device — for example, a daily "off at 4pm" rule that would undo a one-off event wanting the same light on until 11pm.

If an overlap is found, a warning appears before the save completes, listing:

  • Which other schedule and rule it overlaps with, the date, and the affected devices.
  • Where possible, a one-click Exclude "[schedule]" on [date] button — this adds a date exception to the other schedule so it steps aside for that one day, then saves automatically.
  • A Save anyway option if you want to proceed regardless.
What this doesn't catch The check looks about two weeks ahead for regular recurring schedules (and at the exact dates for one-off ones). A conflict that would only show up in a different season — say, a sunrise-timed rule that only overlaps a fixed-time rule in winter — won't be flagged until closer to that date.

Glossary

ScheduleA named group of entities plus one or more rules.
RuleOne on/off pattern within a schedule — days or dates, on/off times, and an action.
EntityAn individual device — one light, one switch, one thermostat.
TemplateA saved, reusable rule or rule set, with no entities of its own.
